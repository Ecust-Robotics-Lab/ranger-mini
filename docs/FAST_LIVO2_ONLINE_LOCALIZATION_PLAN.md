# FAST-LIVO2 在线定位与重定位首轮实施计划

日期：2026-11-06。用户先确认大部分计划，要求快速开发、避免过多防御性设计，录制新查询包后明确要求检查完成即开始开发。本轮授权源码、隔离构建和离线测试；不自动启动设备、底盘、导航、部署生产、提交或推送。

## 目标和路线

使用现有三融合前端与同一C1/C2：冻结地图加载→C2无初值搜索/多帧确认→C1独立初始化与跟踪→LOST后重新搜索。保留人工初值模式。保持既有几何、运动、歧义、时间、TF和代际规则，不增加新的检索框架或算法worker。

首图为 `full_replay_12/map`，UUID `253f573d7a7eabbc363a225ab192cc14`。使用已有在线I/O派生前端，从实际查询配置/程序生成三项来源身份；C1/C2与KISS在 `online_localization_install` 隔离构建，不替换旧安装。PCL默认、small_gicp显式对照，正式+100ms、初始重力对齐开启、Tag关闭。

## 实施与验收顺序

1. 加载正式地图、验证查询身份和运行程序。复用现有内存地点索引，不添加索引缓存服务。
2. 节点增加默认关闭的online_scheduling；在线时最多保留最新两对待处理完整扫描，不取消正在处理的扫描，控制任务保持优先的既有代际语义。跳帧可观察，旧几何证据需新鲜扫描复核才发布VALID；提交和心跳均检查原采样年龄，0.5秒门槛不放宽。
3. 提供默认dry-run的统一入口localize_fast_livo2.sh，支持auto/manual、原速header-clock重放、独立输出、状态/停止、可选RViz。复用设备/时钟/收流/录包/归属清理机制；定位模式不启动B、不输出公共TF，停止无需封存新地图。
4. 先短包核对端到端流程，再390秒原速同包功能检查；使用新282秒独立采集包验证自动初始化/跟踪，人工初值和受控恢复分别验证。原两90秒包作为备用诊断，不要求为重复同类证据额外全部重跑。
5. 测试只覆盖真实改动：过载跳帧、新鲜度、候选交接、人工初始化/自动恢复、取消/切图旧结果、EOF和Ctrl+C；复用相关核心与ROS回归。报告实际成功/失败和分母，不从心跳数量推导定位频率或精度。

### 已知瓶颈与待证实原因

`startup_latency_analysis.json`记录首次C2交接49.514秒、首次C1 VALID 51.494秒。首次VALID前已发布的53份查询诊断中，265个候选有247个在粗配准阶段失败、18个通过粗/精配准。它们是发布快照，不是完整尝试日志，也不是带真值的检索召回率。前端相对首帧累计0.15米在约19.500秒达到；运动是相对支持帧检查，不能直接把19.500秒当所有查询共同的确认时刻。

源码进一步确认：

- 检索仍是自有`radial_pair_distribution_v1`原型，131维，两个64格距离直方图的格宽约1.25米，另有3个协方差特征值比例。它不提供航向；对同一完整点集的刚体不变性不等于对不同可见点集/遮挡的稳定性。当前只取前5个关键帧，没有按地点分散候选。
- 查询对每帧先0.2米体素化，再按数组下标等距抽样到最多2000点，合并2帧。粗配准目标为最多8个关键帧组成的子图，先按下标抽到4000点，随后KISS再做0.2米体素化。KISS法向/FPFH邻域半径仍为0.6/1.0米。密度、局部邻域、重复点和可见范围不一致是优先检验的假设，目前没有特征数量/正确对应标签证明它是唯一根因。
- 所有C2 reject都会清空临时支持并退避0.5秒；已找到的候选在下一轮仍重新走全局检索和KISS。偶发特征失败可能反复中断确认。不能直接删掉清空逻辑或把旧支持当新证据。
- C1交接后约1.98秒包含两次完整邻域歧义验证和一次新鲜扫描复核；它是次级开销，优先改善此前的搜索成功率。

### 一手资料对工程的启发

| 方案/资料 | 与当前问题的关系 | 采用判断 |
| --- | --- | --- |
| [KISS论文](https://arxiv.org/abs/2409.15615)及[作者对scan/submap匹配与采样的答复](https://github.com/MIT-SPARK/KISS-Matcher/issues/73) | 基于局部几何特征建立对应；作者建议考虑体素尺度，或在特征提取后采样，并提醒简单采样可能损害性能 | 首先修正/对照本项目送入它的数据；保留现有锁定版本 |
| [Scan Context官方实现](https://github.com/gisbi-kim/scancontext_tro)及[Scan Context++论文](https://arxiv.org/abs/2109.13494) | 提供地点检索和航向线索；论文讨论横向变化及roll/pitch条件 | 检索召回不足时首选轻量SC对照。官方++扩展包含Matlab评估代码，不视为现成完整C++插件；源码有CC BY-NC-SA声明，本地sc_a_loam许可仍UNRESOLVED，不直接复制 |
| [STD](https://github.com/hku-mars/STD)、[BTC](https://github.com/hku-mars/btc_descriptor) | 用局部关键点/三角形保留对应关系，官方STD有Livox不同视角示例，BTC从积累点云生成描述子 | 作为视角差/重复结构下的备选，不同时接入多个检索器；示例不是本项目Mid-360S性能证明 |
| [3D-BBS官方实现](https://github.com/KOKIAOKI/3d_bbs) | 在地图上做分支定界搜索，可绕开局部特征对应失败；支持重力近似对齐及CPU-only构建 | 若正确地点已检出但KISS仍长期失败，作为第二路线。论文/仓库的GPU时延不能套到本机CPU；不为此升级CUDA/系统 |
| [iBTC官方实现](https://github.com/hku-mars/iBTC) | 用图像辅助区分长走廊等LiDAR困难场景 | 后续候选；当前地图没有现成可直接消费的iBTC视觉地点库，ROS1/图像关联接入比先修现有链路重 |

重力信息可用于归一化描述子和生成粗配准初值，但必须按各采样时刻的姿态将IMU机体系云正确旋到重力参考系；世界+Z对齐不代表机体系云已水平。最终仍恢复/优化六自由度，不锁死roll/pitch，不直接把现有`use_quatro`翻为true。

### 最小改动顺序

1. 固定新包前60秒的少量代表查询及地图，记录每次实际尝试的候选排名、点数、有效特征数、对应数、失败原因、支持状态和分段耗时。对少量查询扩大候选诊断，核验办公室/走廊对应地点是否进入前5；人工区域核验和后验轨迹推导只作诊断，不作为独立真值或输入给在线盲测。无需重新录包或先全量重放。
2. 优先对照粗配准输入：先保留足够空间邻域再提特征，比较候选单帧/短子图与当前8帧目标，统一空间采样尺度；从0.2/0.3米、约8千至1.6万点的小范围实验开始。查询对照5至8帧、约0.5至0.8秒的相对运动补偿积累，合并后体素去重。固定4000点只增加帧数会进一步稀释单帧，不视为有效改进。参数数值是试验起点，不是推荐生产值；不做笛卡尔积大规模扫参。
3. 候选按空间地点分散，先比较5与10个候选；只扩关键帧数可能反复匹配同一地点。第一个通过粗/精配准的候选进入短暂局部验证，用前端相对运动传播后匹配新的独立扫描，并保留其他地点歧义检查。单次无匹配可短暂保留未确认假设，但不增加支持次数、不刷新几何证据时间、不发布VALID；冲突、明确歧义、超时、切图或会话变化仍清除。复用现有support，不新造多假设滤波框架。
4. 若检索覆盖仍不足，再以SC替换/对照现有分布原型，使用重力归一化、适合室内范围的网格、候选航向辅助粗对齐，保留KISS及C1几何复核。若已命中地点而几何仍失败，优先对照3D-BBS；避免把两类故障混为描述子问题。
5. C1约2秒交接成本及短时LOST恢复另作后续优化。短时LOST且前端会话连续时，可先尝试最后接受位姿加相对里程计的局部恢复，失败再全局搜索；这属于有先验恢复，必须与无初值冷启动分开计时。

验收分别记录从首个可用扫描到候选、从满足实际独立运动条件到确认、到首个新鲜VALID三个时间，以及错误地点/歧义、有效扫描数和0.5秒新鲜度。工程目标先争取运动条件满足后2至5秒内确认；不是已验证承诺。本包前约19秒低运动，保持既有运动规则时不能声称开包3至5秒即可VALID。若将来要求静止启动，应单独制定可观测性/先验验证路径，不能仅把静止多帧当独立运动。

每一步单独和基线对照，有效才保留；胜出方案再完整重放282秒并用390秒检查功能回归。不同截取起点可测试冷启动稳定性，但仍来自同一次访问；既有用户路线说明不能支持绝对精度或真实地图外负样本通过结论。本次调研未实施这些实验。
