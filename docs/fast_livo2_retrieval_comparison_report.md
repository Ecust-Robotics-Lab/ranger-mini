# 自有三维检索改进、STD/Scan Context 对照与 GICP 默认切换

日期：2026-11-06。用户明确要求先优化自有检索，和STD、Scan Context比较，再将small_gicp作为默认选项。本轮仅源码、项目内隔离构建和离线测试；未启动传感器/底盘/导航、未接管生产、未提交推送。原有未提交内容保存到 `.runtime/backups/retrieval_comparison_20261106_161941/`。

## 自有检索实现

用户随后要求选择当前最推荐组合并设置默认。推荐现阶段已完成整包验证的“自有v2检索→KISS完整六自由度粗配准→small_gicp精配准→C1确认/跟踪”。SC80在共同几何候选检查中表现更好，但未完成同条件完整C2→C1及GICP整包比较，不能由候选计数断定完整系统更优。该推荐组合已是在线入口默认；本次再次dry-run核验实际参数，并核对现用节点/核心库SHA与通过默认短包检查的程序一致，无需重复改写配置。证据为`recommended_default_verification.json`。

旧版`radial_pair_distribution_v1`保留。新增`radial_pair_multiscale_v2`：

- 原64格/80米的粗距离分布改为三个独立归一化的64格分布：质心径向24米、短点对距离12米、长点对距离48米。分别保留室内细节与较大范围形状。
- 距离在线性相邻格之间分配权重，减少硬分箱边界跳变；对概率做平方根嵌入，再用平方距离比较，减轻大概率格对比较的支配。
- 保留三个协方差特征值比例，也做平方根嵌入；总维数195。固定8192次点对采样，无学习模型和新增运行依赖。
- 保持完整三维距离特征，不依赖roll/pitch为零；体素化和有界点采样仍带有近似误差，不宣称严格数值不变。
- 新索引绑定算法/维数/多尺度参数；旧v1派生索引参数格式保持，v1/v2不能混载。节点增加`global_descriptor`，在线入口增加`--descriptor`，诊断记录所选算法。

本轮没有同时调整查询窗口、KISS采样/门槛、C2运动支持或C1接受规则，因此原速v2/PCL结果主要检验检索替换的效果。候选空间去重、临时支持保留等前轮建议尚未加入。

## 共同数据与评估定义

地图为正式`full_replay_12/map`，UUID `253f573d7a7eabbc363a225ab192cc14`，305关键帧，manifest SHA `e81d4a05a8da6cf3c1badfc0a6171295020bec59e5615408796c92a85b49b247`。查询来自新282秒访问此前完整三融合重放的去畸变云，原包不改。

`prepare.py`冻结136个查询时刻，间隔约2秒；每个时刻分别导出2帧、8帧相对运动补偿云，共272份。前60秒29个时刻为开发段，后段107个时刻为留出段；留出仍来自同一访问，不是另一份独立包。各算法在同协议下使用完全相同点云、候选上限5。除SC的合法前端姿态重力归一化外，查询检索不使用地图位姿参考。

没有外部真值。参考位姿来自上一轮PCL已接受结果的地图—局部修正与同次访问前端运动；首次VALID前使用向后传播参考。**“参考区域覆盖@K”只表示前K候选中有关键帧中心落在估计参考3米内，不是有真值的Recall，也不能证明定位绝对正确。** 参考位置只在检索完成后计算指标，不输入检索器、KISS或在线无初值测试。

共同几何实验对各方法前5候选运行同一个现有KISS和PCL精配准及独立几何门控；相同查询/候选的几何结果复用，不把重复求解噪声当作检索差异。统计“至少一个候选几何通过”的查询数，未执行完整C2时间/运动/歧义状态机，因此不能把它称为首次VALID或整包定位成功率。几何实验与部分构建并行过，不用其时间列作单独性能结论；检索耗时另在无构建/重放并行负载下串行重测。

后段107个查询：

| 自有v1 | 83/107 | 100/107 | 51/107 | 0.166/0.195 |
| 自有v2 | 100/107 | 106/107 | 50/107 | 0.223/0.255 |

前60秒29个开发查询：v1/v2/SC20/SC80/STD覆盖@5分别为27/29、29/29、29/29、29/29、5/29；共同几何通过查询分别11、20、21、22、0。v2/SC在约0.70秒查询上已经出现几何通过，**该查询是一次独立几何试验，仍不满足静止阶段的C2完整确认条件。**

所有已评估的几何接受候选中，没有与估计参考相差超过3米的结果；参考来自既有定位，不能把这一项声称为真实错误接受率为零。KISS内部含其自身采样，重复几何试验出现1至2个边缘查询通过数差异；前一轮主几何试验v1/v2后段为50/52，本轮加入STD室内参数重跑为51/50。两轮均保留，不根据这点差异宣称v2几何通过率提高。

结论：本数据上v2候选排序/区域覆盖改善，SC80的后段共同几何通过数更高。更接近参考的位置候选不必然有更好的点云视角和几何重叠，检索覆盖与配准通过须同时看，不能给出普适检测器排名。

## 原速整包与small_gicp

先完成v2/PCL整包，保持三融合、+100ms、Tag关闭和原门槛：首次VALID 24.394秒，2579个不同有效扫描，初始化后没有DEGRADED/LOST/ERROR，接收年龄最大0.386秒，0个年龄违规。旧版v1/PCL基线首次51.494秒、2309个有效扫描。两者为各一次原速运行，不能由此承诺所有冷启动都降低同样时长。

两次完整运行路径、实际命令和SHA以各自`provenance.json`、`session_logs`和本证据目录为准。`retrieval_phase_complete.json`记录检索对照完成及当时PCL默认，然后才启动small_gicp对照。同v2/PCL与v2/GICP试验的localizer core SHA均为`2e59dc0f9376e4fc57d94f739113d42baa4c5f1871c181f267ff4cc74c55648e`；节点仅在增加所选检索算法诊断前后有构建差异。

检索实验和GICP对照结束后，`config/fast_livo2/localizer.yaml`、节点注册器缺省值及在线/原离线入口/运动验证工具默认注册器改为small_gicp；在线入口默认`radial_pair_multiscale_v2`。共享旧C2配置与旧安装保留v1兼容；在线可显式`--descriptor radial_pair_distribution_v1 --registration pcl_icp`选择旧组合。B后端和生产Lightning默认不变。该默认切换影响C1初始化粗/精、跟踪以及C2精配准；KISS仍是C2全局粗配准。

隔离默认构建退出0；33项核心检查及small_gicp默认下3项在线ROS回归通过。ROS回归首次仅source FAST安装，缺少ws_nav消息环境，导入失败；补齐ws_nav安装后通过，失败日志保留。默认dry-run核对online的v2/small_gicp、原离线入口small_gicp，无设备启动。8秒三融合默认入口EOF检查和最终完整性结果见本证据目录。390秒旧同源包本轮未重新做GICP整包验收，原连续新鲜度限制不追认为已经解决。
