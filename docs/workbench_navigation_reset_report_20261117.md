# 失败后的独立规划控制重置 — 2026-11-17

用户报告单点失败后无法停止旧规划、重新启动规划控制。本轮完成软件实现、构建、离线及隔离ROS验证；没有启动机器人设备、操作CAN或发送实车目标/速度，没有提交推送。

## 原因

记录 `live-0e9da78bf0ab4b6898f7cb28484d9f46` 中目标已经返回FAILED，原因为start_live_obstacle_collision，控制输出已撤销。没有证据证明当时计算进程挂死或旧目标仍在执行。

页面只对活动目标开放“取消并停车”，目标失败后按钮被禁用；没有单独清除终态任务、重建规划控制的入口。“停止自有会话”则停止整套自有底盘/传感器/定位/导航，不能用于只重置规划控制。原后台保留就绪的JAX进程是为了复用预热，不表示仍在执行旧目标。

## 新行为

新增网页“重置规划控制”，对应认证/来源检查下的POST `/api/v1/navigation/reset`。当前会话READY即可请求，失败任务或定位暂无效不会禁用此按钮；新目标仍必须满足原定位、CAN和输入条件。

1. 先撤销自主使能。若有工作台自己的活动目标，按真实Action协议取消并等结果；无法确认取消完成则报告失败。导航端`/navigation/reset`（std_srvs/Trigger）拒绝尚有活动目标的请求，不中止外部目标。
2. 清除目标、路线、预测轨迹、最终验证确认标识和历史，递增控制/路线代际。旧异步结果失效，保留定位、观测缓存、地图、原始记录和设备会话。
3. 非阻塞退出仅属于该协调器的计算子进程；2秒未退出则结束该子进程。换nonce后重新启动和预热，旧邮箱/旧进程结果不能接回。独立门禁仍运行，重置期间没有自主使能或有效运动输出。
4. 页面显示重置进度，期间禁止新目标。必须等本次generation、新worker nonce、READY与IDLE的新鲜反馈后才清除旧任务并报告完成。完成后由用户再次执行目标，不自动重试原目标。失败可重试，停止自有会话可取消重置，不等待完整预热期限。

同时修复受管会话联动：原session_probe把worker未就绪直接视为navigation健康丢失；navigation会话有1秒健康丢失宽限，故直接重启JAX会被监护提前停止。现在只对明确RESETTING、有效steady起始时间、35秒内且无worker错误的阶段允许继续初始化；状态消息仍须新鲜，定位、FAST/wheel输入、门禁和发布者检查不变。过期、未来起始时间、错误、普通执行中的worker不就绪均不享受此条件。运动许可与此进程健康判断独立。

定位400ms、静态总裕量2.5cm、实时避障及100ms租约、正式低延迟前端均保持原配置。重置不删除实时障碍证据，也不使碰撞目标变成可达。

## 使用与当前状态

更新后正常重新运行工作台、网页显式启动自有会话加载新版。单点失败后可点击“重置规划控制”，等显示就绪，再选点执行；“取消并停车”仍用于结束活动目标，“停止自有会话”用于停止整套自有设备。

结束boot/PID核对见final_identity.json：工作台、底盘、导航、定位四会话均STOPPED、不存活，隔离测试受管会话均完成清理。Agent没有代停/重启用户设备。现场按钮和重新导航效果仍PARTIAL；以上全部是软件、GPU与隔离ROS证据。原失败目标的实时障碍原因保留，实车出门/坡道/往返未通过状态不变。
